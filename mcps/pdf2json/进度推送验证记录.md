## 一、实现说明

新增 `demo_progress` MCP 工具，逐步推送标准 `notifications/progress`：
`progress=1..steps`，`total=steps`，`message="<前缀> i/steps"`。
无需 PDF 与 VLM，可独立、确定性执行，用于验证「MCP server → 后端 → 前端进度条」全链路。

调用方式：`demo_progress(steps=5, delay_ms=300, message="进度验证")`。

关键点：进度通知只在客户端请求带 `_meta.progressToken` 时才会被发送
（标准 MCP 语义），opencode 后端调用工具时自带 progressToken，因此正常。

## 三、异常项 ⚠️（已修复 ✅）

此前全量浏览器 E2E `packages/app/e2e/regression/session-timeline-mcp-progress.spec.ts`
在本机失败：时间线测试 harness 页面（标题 "Timeline visual stability"）在进度断言之前
30s 内未渲染，被应用错误边界替换为 "Something went wrong"。

**根因（生产缺陷，非测试环境问题）：**
`packages/app/src/pages/directory-layout.tsx` 创建了 `modelContextHost`
（`createModelContextStore()`）并引入 `McpModelContextProvider`，
但从未在组件树中渲染该 Provider。`packages/app/src/components/mcp-app-view.tsx`
在组件顶部无条件调用 `useMcpModelContext()`，无 Provider 时抛
`"McpModelContextProvider missing"`，导致挂载任一 `ui://` App 都会触发应用级错误边界，
整个页面（含时间线）被空白错误屏替换 —— 这是 MCP App 公共渲染路径的真实 bug。

**修复：** 在 `directory-layout.tsx` 的 `DirectoryDataProvider` 中，
用 `<McpModelContextProvider host={modelContextHost}>` 包裹 `LocalProvider` 子树，
与其他 Provider（McpAppHostProvider / McpAppRendererProvider）同级补全了缺失的模型上下文。

**验证：**
- `session-timeline-mcp-progress.spec.ts`（2 条）：通过 ✅
- `session-timeline-mcp-app.spec.ts`（3 条）与 `mcp-apps-panel.spec.ts`（2 条）：全部通过 ✅
- `packages/app` `tsgo typecheck`：无该文件报错 ✅
